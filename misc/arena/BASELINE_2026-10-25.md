Engine development is paused so gameplay can proceed. This is a reusable
Windows x64 .NET editor baseline with bounded Vulkan Forward+ checks, not a
production qualification or an FPS claim. No native rebuild or new GPU run was
needed to publish the already-tested editor.

## Use on another Windows machine

1. Download the ZIP, `SHA256SUMS`, `baseline.json`, this quickstart and
   `verify_frozen_baseline.py` from the release. Verify the ZIP hash with
   `Get-FileHash -Algorithm SHA256 <zip-path>` against the value above.
2. Extract into a new regular directory, keeping the editor, console wrapper,
   `GodotSharp/`, `NuGetFeed/`, notices and `_sc_` together. Do not replace only
   an EXE. Install the .NET 8 runtime and a compatible .NET SDK for C# development;
   qualification used SDK `10.0.203`. No C++ toolchain is needed to use the ZIP.
3. With Python 3.10 or newer, run the downloaded verifier from outside the bundle:

   ```powershell
   python verify_frozen_baseline.py "D:/Tools/ArenaEngine/<extracted-bundle>"
   ```

   It must report `status: verified`, 370 artifacts and the identities above.
   It is read-only and does not start Godot. Later editor-generated extra files
   are allowed but are not verified. Use an idle directory without links/junctions.
4. For a consumer explicitly adopting these APIs, use the project-local
   `NuGet.Config` example in [ARENA_ENGINE.md](https://github.com/vladyslav-zaichyk/godot/blob/arena-4.7.2-baseline-2026-10-25/ARENA_ENGINE.md#another-windows-machine),
   pointing at this bundle's `NuGetFeed`, and pin:

   ```xml
   <Project Sdk="Godot.NET.Sdk/4.7.2-arena-dev-g26f1b2b.845">
   ```

   The editor and generated bindings must come from the same bundle. This
   publication does not migrate the Arena game's current stock `4.7.2` SDK or
   change its renderer defaults.
5. Launch `godot.windows.editor.x86_64.arena_dev.mono.exe`. Custom game export
   templates and other platforms/backends are not provided by this release.

The guide inside the original ZIP predates this freeze and refers to a missing
`verify_bundle.py`. Use the separate verifier above. Do not repackage an editor
directory after use: its self-contained settings/cache may contain local paths.

## What differs from stock Godot

| Included capability | Purpose and boundary |
| --- | --- |
| Shared MultiMesh buffers and BufferRD | Borrow caller-owned transforms/commands and expose readonly shader storage; ownership and rendering-thread rules remain explicit. |
| re-spirv runtime-array support | Removes the earlier BufferRD optimizer fallback. |
| E5 shader-driven MultiMesh | Stable GPU ID indirection without the redundant per-slot transform bank. |
| E6a mesh RD access | Borrow engine-owned vertex/attribute/skin/index buffers; no external-buffer attachment. |
| E8 shader-owned history | Previous GPU state and motion-vector inputs, with caller-managed lifecycle/history. |
| E9 bounded command spans | Multiple compatible indirect commands per MultiMesh owner, not arbitrary cross-mesh batching. |
| E10 GPU-sourced draw counts | Checked RD count-buffer draws and MultiMesh count consumption, with ownership/alias guards. |
| E12 checked indirect compute | Transactional indirect dispatch validation and argument/alias checks. |
| E13a–c occlusion scheduling | Selected occluder depth, synchronous producer, remaining depth, color/velocity; perspective and native TAA/E8 admission. Hi-Z selection logic belongs to the consumer. |
| E13d ordinary instancing | Preserves ordinary opaque repeat groups across the split depth phases. |
| E13e shadow compatibility | One Orthogonal directional split; shadows retain complete fallback commands and immutable IDs despite camera selection. |

Contracts and procedural labs are under `misc/arena/`; generated APIs are in
the exact matching managed SDK. These are rendering extensions, not a complete
swarm simulation, combat or networking system. E11 shared geometry-history/cache
remains research, not an implemented animation-cache feature.

Native build checks passed 139 CPU cases / 954,974 assertions; 12 managed
consumer families compiled. Integration game commit
`936c4eac27473a619e470225c539ee7dee88011f` passed eight basic stages on this exact
editor: seven GPU processes and one CPU preflight. They include E13d's 24

shutdown diagnostics. Shadow scope is one owner, 16 slots, one Orthogonal
directional light, native TAA/E8 and fixed boxes/root poses. Real-VAT temporal
checks passed separately; this does not qualify VAT plus shadows.

The latest timing evidence, game `3f76361eaf84611f2ba48919e49e386a894f1e07`,
retains 23 completed windows / 342,220 frames across three incomplete cohorts.
External GPU activity prevented a complete clean A/B. Do not pool the cohorts

## Resume and upgrade policy

The engine epic is parked. Return to game development on the current accepted
game path; newer APIs stay opt-in. Resume engine changes for a measured
bottleneck that public APIs cannot solve, or a reproducible correctness defect.

Keep this tag and binary immutable. For a fix or upstream upgrade, create a new
candidate branch, use a new exact SDK/build identity, and run affected correctness
and matched performance gates. The [upgrade procedure](https://github.com/vladyslav-zaichyk/godot/blob/arena-4.7.2-baseline-2026-10-25/ARENA_ENGINE.md#upgrade-procedure)
remains applicable. To inspect the frozen source:

```powershell
git clone --branch arena-4.7.2-baseline-2026-10-25 --single-branch https://github.com/vladyslav-zaichyk/godot.git
```

To rebuild the native source, use a clean checkout of the full native SHA and
the toolchain/commands in the bundled `evidence/native-build/manifest.json`.
The generic build helper creates a new build identity and is not a promise of
byte-identical reproduction of this ZIP. Native flags were Windows x64 editor,
Mono/tests enabled, `dev_build=no`, `optimize=speed_trace`, `d3d12=no`,
`accesskit=no`, `angle=no`, debug symbols enabled and `lto=none`; .NET SDK
`10.0.203`, Python 3.13.1, SCons 4.8.1 and VS 2022 v143/Windows SDK
10.0.22621.0 were recorded. A rebuilt executable needs its own qualification.
